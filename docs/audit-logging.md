# 审计日志

管理端“审计日志”用于回答谁在何时修改了什么，以及数据库是否已保存、HTTP 请求是否失败。普通心跳不进入审计；节点状态变化进入节点事件，DNS 运行时诊断仍查看服务端和客户端运行日志。

## 写入语义

- 用户创建、状态/设备上限、密码、删除，用户组及成员、子网、API 密钥创建/撤销、网络/DNS/路由、集成及整组通知配置、节点路由/强制下线/删除采用事务审计。对应数据库变更与审计一起提交；审计写入失败会回滚该事务。
- 一次 API 请求可能执行多个事务或调用 WireGuard、刷新 ACL。`outcome=committed` 表示对应数据库变更已提交，不代表后续外部步骤完成。后续失败另记 `failed`，可通过 `request_id` 关联；`committed_changes` 是该请求已提交的事务数。数据库事务不能回滚已经执行的外部动作。
- 中间件补齐 POST/PUT/PATCH/DELETE 和备份下载；已有事务记录时不重复记录请求成功。尚未接入字段快照的动作只提供请求结果，不编造字段差异。
- 重启记录的是“请求重启”，不能据此认定进程已完成重启。
- 登录及认证失败、请求兜底日志等待写入完成，最多并发 16 个；超过上限丢弃并累计计数、按指数间隔告警。关键事务审计不使用这个丢弃策略。
- 管理员接口 `/api/v1/admin/audit-health` 返回进程启动以来的 `failed_writes`、`failed_transaction_writes`、`dropped_events`，审计页面显示非零计数。重启后计数重置，历史告警需查运行日志。

## 认证拒绝降噪

- 签名及其他声明有效、账号仍可用且仅 Access Token 到期的请求，仍返回 HTTP 401 / `1002`，但不写 `auth.rejected`。运行日志以 debug 记录，`audit-health.access_expirations` 统计本进程遇到的次数；该计数不代表续期成功或失败。
- 无效签名、缺失凭据、禁用/删除账号及刷新失败仍保留认证拒绝审计。刷新失败记录在 `/api/v1/auth/refresh`；可通过已知会话归属到用户，不记录 Token 或哈希。外部错误码与消息保持兼容，不能仅按 `1002` 过滤日志。
- 拒绝事件按固定 5 分钟窗口及用户、来源 IP、接口、User-Agent、状态和原因合并。首条立即保存，后续原子累加 `occurrences`，保留首次及最近时间、首次及最近请求 ID；不同原因或不同窗口不会合并。页面和 CSV 显示次数与时间，分页条数表示事件组数。超过审计并发上限的事件仍计入 `dropped_events`。
- 共享 Rust 客户端（桌面端及 CLI）在认证请求前检查服务端返回的有效期，提前 60 秒刷新；并发请求共用一次刷新，仍保留收到 `1002` 后刷新重试一次的兜底行为。
- 这些规则只作用于部署后的新事件；既有历史审计不删除或改写。

## 字段和隐私

记录操作者 ID/当时名称、API 密钥 ID/名称、目标、请求 ID、来源 IP、User-Agent、操作、结果和真正变化的字段。密码及哈希、私钥、PSK、Token、集成密钥、通知 Webhook URL 只记录“已变更”。不记录 HTTP 请求正文、授权头和密钥明文。

`VPN_TRUSTED_PROXIES` 可填写逗号分隔的精确代理 IP（支持 IPv4/IPv6，不接受 CIDR）。默认以 TCP 对端为来源，不采信 X-Forwarded-For。只有直接对端属于可信代理时才从右向左跳过可信代理，选取首个非可信地址；无传输地址时留空。代理必须正确追加或覆盖来源头。

## 查询和导出

`GET /api/v1/admin/audit-logs` 仅限管理员，支持 `from/to`（Unix 毫秒）、`user_id`、`username`、`action`、`category`、`resource`、`outcome=success|failed` 和分页。默认最近 7 天、每页 20 条，最多每页 100 条。相同时间按 ID 稳定排序。

旧事件名保持兼容；历史记录没有操作者名称或字段差异时明确显示缺失。`network.dns.update` 表示网络配置事务中包含 DNS 字段变化。CSV 导出当前筛选结果，最多 10000 条，导出安全的固定列并防止表格公式注入，不导出原始 metadata、User-Agent、配置或密钥值。

## 保留和恢复

`VPN_AUDIT_RETENTION_DAYS` 默认 180 天，0 或非法值回退 180。现有每天清理任务继续工作。

备份仍可包含审计日志，但恢复时保留当前数据库的审计历史，不删除或导入备份内的审计记录，防止回滚历史或伪造历史。恢复事务记录备份内容 SHA-256、生成时间、格式版本、对象数量及保留历史标记；返回值 `audit_logs=0` 表示导入的日志条数。历史用户被删除或恢复后，已有审计中的操作者快照保留。
