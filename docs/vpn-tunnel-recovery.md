# VPN 数据隧道自动恢复

2026-09-15 排查发现站点客户端在断网后持续报告 `ConnectionExpired`，HTTP 心跳恢复但 WireGuard 未重新握手。该错误表示 WireGuard 会话过期，与用户账号或审批到期无关。

共享的 vpn-cli 用户态转发引擎现支持 Linux CLI 与桌面客户端：

- 首次握手 15 秒仍未完成、握手记录超过 180 秒，或底层报告 `ConnectionExpired` 时进入恢复流程。空闲连接也以握手验证对端，业务 HTTP/ICMP 的成败不作为重连依据。
- 首次恢复后按 30 秒、60 秒、最多每 60 秒的间隔重试，更新 UDP 源端口并显式发起握手；新的 socket 创建失败时保留旧 socket。
- 保留现有 TUN、密钥和路由，不重启服务端或调用外部进程，不创建并行转发循环。用户断开仍由原有 shutdown 与 supervisor 清理路径处理。
- 只有本轮恢复之后的新认证握手才算恢复成功，旧握手记录不能清除恢复状态。
- 客户端“已连接”要求 HTTP 管理心跳和 WireGuard 握手同时健康。管理心跳恢复不再单独把客户端状态改成已连接。

这不保证目标应用可用，也不会绕过用户授权、ACL 或修复外部防火墙。服务端原有节点 online 字段仍表示管理心跳在线，不能作为端到端应用可达性的证明。运行中的旧客户端需升级才获得此修复。

验证覆盖重试限频、旧握手不能误报恢复、真实 WireGuard 重新握手、UDP 源端口更新、两通道状态合并，以及退出/错误状态不被健康更新复活。
