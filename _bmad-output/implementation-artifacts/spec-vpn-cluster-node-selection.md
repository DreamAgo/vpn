## 目标

新增可跨主机部署的 VPN 网关。保留一个控制面管理登录、VPN IP、终端限额和访问策略。每个网关有独立的 WireGuard 密钥和公网 UDP 地址，在本机终止客户端隧道。客户端连接时自动选择可用网关，当前网关故障时重新选择。

## 范围

- 单控制面负责写 SQLite，网关经私有网络上的双向认证接口领取配置。控制面高可用独立规划。
- 管理员指定一个默认网关，现有内置网关作为初始默认值。具有现有 VPN 使用权限的客户端可直接使用默认网关。旧客户端继续使用默认网关。
- 管理员按客户端设备逐台授予额外网关的访问权限。新网关默认对所有客户端关闭额外访问。候选列表只下发默认网关及该设备已获授权的网关，并过滤未就绪节点。控制面创建和续订租约时再次校验现有 VPN 权限、设备身份和额外网关授权，网关仅为持有效租约的设备配置 WireGuard peer。
- 额外网关授权绑定已验证的设备身份。同一账号下的其他设备各自授权，设备名称复用不转移权限。撤销额外网关权限时回收相关租约，客户端重新在仍可用的授权范围内选路。
- 管理员可按设备指定目标网关，也可恢复自动选路。目标只能是默认网关或该设备已获授权的额外网关。指定目标持续生效，优先于测速结果；撤销目标网关的设备授权时清除指定，恢复自动选路。
- 控制面保存带版本的目标配置。支持集群的在线客户端在下一次成功心跳收到目标变更，目标就绪时发起切换；离线客户端在下次连接时应用最新配置。设备身份和 VPN IP 沿用现有记录。旧客户端继续使用默认网关，后台显示该版本不支持远程切换。
- 后台分别展示指定网关、实际网关和切换状态。客户端完成目标网关握手并确认当前配置版本后才显示切换成功。保存目标和恢复自动选路均写入审计。
- 每个终端只有一个有效网关归属。换网关沿用原设备身份和 VPN IP。先确认旧归属撤销或租约失效，再启用新归属，避免同时放行。
- 保留飞书登录、授权到期、设备限额、DNS、组路由及站点网关语义。集群内的返回流量经私有加密互联送达当前归属网关。网关未应用当前授权策略时禁止接入；失联后只在有效租约内转发。
- 单机保持原有部署方式。正式客户端和镜像按统一 Release 工作流发布。

## 选节点

| 场景 | 行为 |
|---|---|
| 首次连接或网络切换 | 仅有默认网关时直接连接。有额外网关授权时，并行测量可用候选，按 UDP 探测成功率和往返时间排序，探测结果无法分出优先级时先尝试默认网关。使用 WireGuard 握手确认，失败则尝试下一候选。 |
| 已连接且健康 | 保持当前网关，避免因短时延迟波动而重建隧道。 |
| 管理员指定目标网关 | 目标就绪且获授权时，即使当前连接健康也切换。目标未就绪时保持现有健康连接；切换失败时按现有退避在获授权网关内恢复连接。保留指定目标，待目标恢复后重试，并显示待切换或失败原因。 |
| 当前网关不可用 | 有界重试后切到下一个获授权且可握手的网关；沿用设备身份、VPN IP 和授权。 |
| 默认网关故障且设备无额外网关授权 | 显示默认网关不可用，并按现有策略退避重试。 |
| 现有 VPN 权限已失效 | 拒绝连接，包括默认网关。 |
| 仅有旧版注册响应 | 沿用响应中的单一地址。 |
| 控制面失联 | 存量隧道可用至租约到期；新增和跨网关切换暂停。 |

## 实现落点

- `crates/vpn-server/src/services/peer_service.rs` 和 `migrations/` 保存网关状态与终端租约，复用现有终端注册、IP 分配和授权撤销。
- `crates/vpn-server/src/main.rs`、`crates/vpn-wireguard/` 与 ACL 服务增加网关运行模式、租约过期清理及跨主机路由。仅广告已经就绪的网关；UDP 探测限速，响应不大于请求。
- `crates/vpn-api-types/src/peer.rs` 增加可选候选网关、网关选择及心跳下发目标契约。探测不重复注册，只有确定尝试的候选才申请租约。
- `frontend/src/` 增加集群管理入口，支持指定默认网关、按设备授予或撤销额外网关访问权、指定目标或恢复自动选路，并显示实际网关与切换结果。
- `crates/vpn-cli/src/daemon.rs`、`crates/vpn-mobile/` 和 Android 隧道服务接入选路及重连。桌面复用 CLI；iOS 随 Packet Tunnel 基线接入。
- `docker/` 与 `docs/deployment.md` 提供双网关部署、接入凭据、互联网络和排障示例。

## 验收

- 两个独立网关均就绪时，客户端选可握手且延迟较低的网关；人为阻断其 UDP 后，客户端切到另一网关并保留 VPN IP。
- 两台客户端分接不同网关时，按现有权限访问彼此、站点路由和内部 DNS。撤销权限后，任何网关都无法继续绕过授权访问。
- 网关重启或断开控制面时，旧租约到期后停止转发；并发切换不会产生双重归属。
- 同一账号下，设备 A 已获新网关授权、设备 B 未获授权时，只有 A 能连接新网关。B 即使直接提交节点 ID 或复用 A 的设备名称也会被拒绝，并可继续使用默认网关。
- 撤销 A 的额外网关权限后，相关租约被回收且不可续租。默认网关故障时，无额外授权的设备只重试默认网关。
- 已连接默认网关的设备 A 收到管理员指定的已授权目标后，即使默认网关延迟更低也执行切换。成功后 IP 不变，后台显示实际网关已更新。目标离线时后台显示待切换，原健康连接继续工作。指定未经授权的目标时服务端拒绝保存。
- 单机与旧版响应兼容测试通过。集成测试覆盖注册、重连、租约和授权，Linux 双主机验证原生 WireGuard 与混淆 UDP；桌面和 Android 通过实际连接测试。


## 验证结果

- Linux 网络命名空间实测两个 WireGuard 网关。验证默认网关限制、设备单独授权、后台指定、撤权、旧租约隔离、VPN IP 保持、跨网关通信、DNS、站点路由和路由恢复。
- 实测有额外网关租约时撤回单机部署。仍有旧互联接口时拒绝启动，拆除后同一数据库恢复两台设备。
- 服务端和 WireGuard 测试、严格 Clippy、CLI 测试、macOS 桌面编译及切换状态测试、Android 单元测试、后台生产构建及 ESLint、两份 Compose 配置解析通过。
- 本次 Linux 实测使用原生 WireGuard。UDP 混淆双网关、桌面和 Android 真机连接仍待验证。当前主线没有 iOS Packet Tunnel 基线。
